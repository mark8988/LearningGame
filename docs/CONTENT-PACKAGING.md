# 正式遊戲題庫打包（CF-C）

## 從教材到遊戲

1. 啟動本機內容工廠 `http://127.0.0.1:5088/`，完成教材擷取與必要的人工確認。
2. 選單元及模型，產生正式批次，逐項對照教材核准題目與知識條目。模型預覽不能打包。
3. 在教材頁「把學習帶進冒險」勾選已審核批次。同一教材可合併多個單元，同一單元只選一批；填寫題庫名稱後按「打包所選單元」。未符合條件的批次會顯示原因。
4. 按「下載遊戲題庫 JSON」。在遊戲長按家長入口並通過算術驗證，選「加入題庫 JSON」，確認加入，再選「切換題庫」。不需要人工修改 JSON。
5. 等待「離線已就緒」，之後可斷網重開並進入 3D 地圖、戰鬥、錯題複習及收藏流程。遊戲不需要連線到工廠或模型。

## 打包條件

- 教材必須可用且已完成必要確認，年級為台灣國小至國中（1–9）。批次須對應目前教材文字、單元及歸類。
- 每單元至少二十題；不設題數上限，不因五十題截斷。所有實際產生的題目均需核准；知識條目須達到該批次的最低數量並通過來源檢查。退回與未核准條目不會納入。
- 檢查題型、解析、來源頁及引文、重複題、知識點對應與選擇題答案位置分佈。失敗指出相關檔案、欄位或條件；人工仍需確認學術正確性。
- 舊批次若不足二十題或缺少知識點規劃，需補充教材或產生新版批次。原草稿與歷史均保留。

## 格式與版本

輸出沿用 `learning-adventure:pack` v1，包含題目、關卡、圖鑑、道具、3D 裝扮、掉落與成就，另加 `knowledge-points.json`。只使用審核通過的教材題目，不混入內建展示題。

`pack.json.provenance` 保存來源文件、來源指紋、單元頁碼、批次及審核版本。每題保存知識點、來源引文、草稿 ID 與審核時間；家長錯題清單可查看知識點與出處。目前不是正式課綱編碼，也沒有知識點掌握度統計。

相同內容與名稱會重用原始快照；修改名稱、來源或審核版本會建立新 ID／版本。每份題庫獨立保存進度，目前不自動遷移舊快照的進度。同 ID 不同內容仍拒絕覆寫。

## 本機保存與限制

工廠保存於 `factory-data/packages/`，不發布 GitHub／Pages。教材、草稿、模型嘗試與測試素材均保留。來源或審核變更後，舊快照停止下載；已下載或匯入的離線副本仍可使用，無法遠端撤回。

遊戲既有匯入限制為每檔 5 MB、最多十份匯入題庫。檔案過大時選較少單元分包，不會自動刪題。請自行保管下載檔與存檔備份。

離線匯入檢查格式、引用、知識點、頁碼與審核欄位；來源指紋不是數位簽章，不能在離線端證明審核者身分或重新核對原教材文字。

## 驗證方式

```sh
npm test
npm run test:factory
node scripts/check-factory-contract.mjs
npm run build
npm run build:factory
npm run test:factory:e2e
```

合約檢查使用 .NET 測試實際輸出的 JSON 交給遊戲驗證器。工廠 E2E 在隔離資料目錄中以自編教材與真實 Qwen 產題，經審核、下載、匯入後，斷網完成一關並複習錯題；不會核准使用者的正式教材。
