# 森知冒險 LearningGame

國小至國中學科複習的 3D 學習冒險。依據 [ARCHITECTURE.md](ARCHITECTURE.md) 分階段開發；**小屋、地圖、角色與戰鬥使用真正的 WebGL 3D**，題目及功能面板使用 React DOM。

## 本機執行

需求：Node.js 24、npm、支援 WebGL 2 的現代瀏覽器。資產檢查腳本使用 Node.js 原生 TypeScript 載入。

```sh
npm ci
npm run dev
```

開啟終端列出的本機網址。滑鼠拖曳／單指拖曳旋轉場景，滾輪／雙指縮放。遊戲適用平板橫向，也提供手機版面。

```sh
npm test          # 純函數、資料包、存檔、狀態機測試
npm run check:assets # 3D 服裝模型、錨點、部位及幾何尺寸檢查
npm run check:content # 題數、解析、答案分佈、難度及圖鑑完整度檢查
npm run build    # TypeScript 檢查與正式靜態網站建置
npm run preview  # 預覽 dist 正式建置
npm run test:e2e # Edge 瀏覽器，平板觸控與手機主流程測試
npm run test:offline # 正式建置斷網後通關、購買、擺放及重開
npm run build:factory # 建置本機內容工廠介面
npm run test:factory # ASP.NET Core 後端測試
npm run test:factory:e2e # 上傳、產題審核、打包、匯入及離線遊玩
node scripts/check-factory-contract.mjs # 後端測試後，驗證內容包與遊戲格式相容
```

E2E 預設使用本機 Microsoft Edge，不會自動安裝瀏覽器；若環境沒有 Edge，請在 `playwright.config.ts` 改用已安裝的 Playwright Chromium。測試會自行啟動 4173 埠的本機網站。

## GitHub Pages 部署

推送到 `main` 後，`.github/workflows/pages.yml` 會使用 Node.js 24 安裝鎖定依賴、執行單元測試、建置並部署 `dist/`。GitHub 儲存庫 Settings → Pages 的 Source 須設為 **GitHub Actions**。

Vite 使用相對資源路徑 `base: './'`，可部署在 `/LearningGame/` 子目錄。網站只發布 `dist/` 靜態檔案；本機憑證、測試產物、工作紀錄及舊專案流程模板均不納入版本控制。瀏覽器存檔依網站來源區分，本機開發的進度不會自動轉移到線上網站。

## 開發範圍

完整階段與驗收紀錄見 [docs/PROGRESS.md](docs/PROGRESS.md)。

- Phase 0：React 18、Vite、TypeScript、Tailwind、Zustand；JSON 型別與內容驗證、`SaveRepository`、starter 家具庫存、3D 空小屋與角色。
- Phase 1：線性解鎖地圖、3D Boss 戰鬥、答題解析、錯題池、等級／傷害公式、勝敗與金幣／經驗／星等。
- Phase 2：通關掉落與 3D 開箱、重複轉換、家具／服裝／藥水商店、3D 商品預覽、購買確認、戰鬥補血。
- Phase 3：3D 小屋 12×8 格子佈置、滑鼠／觸控拖放、旋轉、移動／收回、碰撞檢查、收藏率與稱號。
- Phase 4：七部位 3D 換裝、衣櫃、商店試穿、小屋／戰鬥／結算同步、模型資產檢查。
- Phase 5：知識／道具圖鑑、3D 複習小徑、五項成就與自動獎勵；60 題、15 篇附圖知識、20 款道具。
- Phase 6：家長驗證、學習報表、題庫／存檔備份還原、內容包獨立進度、PWA 離線、音效及閱讀設定。
- CF-A：本機 ASP.NET Core 8 內容工廠，上傳 PDF／EPUB／圖片、文字擷取／本機 OCR、學制科目歸類、單元切分與家長確認。
- CF-B：本機 Qwen／Ollama 產生選擇題、填空題與知識草稿，逐項人工審核及來源對照，支援台灣國小至國中教材。
- CF-C：已審核單元打包、來源與版本綁定、家長模式匯入及離線遊玩。操作見 [CONTENT-PACKAGING.md](docs/CONTENT-PACKAGING.md)。

目前版本 0.11.0，遊戲軌 Phase 0–6、CF-A–CF-C 本機流程已開發。新遊戲贈送四件家具；服裝可從商店及冒險取得，再由小屋或側邊導覽進入衣櫃穿戴。可上傳教材、整理文字、產生混合題型並審核；已核准單元可打包後匯入遊戲。內建仍為小三自然展示包，沒有內附完整國中課程。

## 程式組織

`src/app/` 畫面；`src/components/` 程序式 3D 場景與模型；`src/stores/` Zustand 遊戲狀態；`src/logic/` 可測試純函數及存檔介面；`src/data/` Zod 型別、格式與跨檔引用驗證；`content-packs/science-g3/` 五單元、60 題示範資料；`tests/` Playwright 流程。

示範題庫僅供開發測試，非課本擷取內容，正式教材須經內容工廠及人工審核。`scripts/generate-demo-pack.mjs` 可重新產生展示包，執行會覆寫內建展示 JSON，請勿用於保留人工編修的內容。

## 存檔與數值

存檔 key：`learning-adventure:save:v1`，變更後 debounce 500ms 寫入，頁面隱藏或關閉前補寫。損毀檔備份到 `:corrupt:<時間>`；不支援的版本保留原檔並停用覆寫。瀏覽器限制儲存時會提示；無帳號與雲端備份，清除網站資料會移除存檔。

匯入題庫另用 `:pack:<編碼後的內容包 ID>` 保存各自進度；內建包沿用原 key。家長模式可匯出／還原，還原前需確認，無效資料或儲存失敗不取代目前進度。

等級在進戰鬥時固定，答對即得 10 XP，通關再得 50 XP；未結算金幣在敗退時不發。提前擊敗 Boss 的全對獎勵與星等，依本場實際作答題數計算。題庫大小依教材而定，每次挑戰最多隨機抽十題，通常混入約三成錯題（十題中最多優先三題）；若一般題不足，再由其餘錯題補滿。短題庫只抽實際題數並按比例調整 Boss 生命，同場不重複。進度與戰鬥數值不受外觀影響。

3D 採 React Three Fiber 8 搭配 React 18（[官方版本相容說明](https://r3f.docs.pmnd.rs/getting-started/installation)），不需要外部模型、貼圖或字體服務。未提供 WebGL 時會顯示明確提示。

## Phase 2 獎勵與商店

每關必掉一件道具，25% 機率再掉一件；普通／稀有／史詩權重為 70%／25%／5%，每關有自己的史詩限定品。`content-packs/science-g3/drops.json` 定義掉落表，載入時檢查道具、稀有度及單元引用；`src/data/gameConfig.ts` 集中管理權重、定價帶、上限及補血設定。

重複裝扮轉為 30 金幣；家具可持有九件，滿額後的掉落同樣轉為 30 金幣。所有獎勵在勝利結算時一次入庫，開箱只負責演出，未開箱離開或刷新也不會失去獎勵。失敗不發金幣及掉落。

商店購買會先確認，金幣不足、重複裝扮或庫存滿額時禁止購買。HP 藥水每瓶 25 金幣，最多 99 瓶，戰鬥中回復 50 HP 且不超過生命上限；滿血、答題解析中及勝敗確定後不能消耗。使用不消耗答題回合。藥水是消耗品，不計入外觀收藏。

舊版 v1 存檔缺少 `potions` 時自動補零，保留原有金幣、經驗、收藏與關卡進度，無須重置。

## Phase 3 小屋佈置

從家具箱拖曳到 3D 地板格子，也可先點選家具再點格子。單指觸控與滑鼠共用 Pointer Events，綠框代表可放，紅框代表出界或同層重疊；桌椅可疊在地毯上。旋轉交換佔格寬高。取消、放到場景外或中斷觸控都不會改動原有位置。

點選場景內家具或「已擺放」清單可移動；收回只減少房間裡的擺放數量，不刪除庫存。購買及掉落增加的是總持有數，家具箱顯示「總持有 − 已擺放」的可用數量。每次成功操作沿用自動存檔，回小屋或重新整理後仍顯示相同佈置。

編輯時採固定等角 3D 視角，互動格子由同一相機投影產生，依視窗大小同步更新；回到小屋可自由旋轉。模型依 JSON 的佔格尺寸調整，包含商店家具及限定掉落家具。鍵盤可用方向鍵選格、Enter／空白鍵擺放，Esc 取消。

家具收藏率以不同款式計算，不計重複數量或服裝。稱號為「溫馨新手」；擺放三件升為「溫馨巧手」，六件且收藏率至少 50% 為「森林設計師」，十件且收藏率至少 75% 為「佈置大師」。

## Phase 4 人物換裝

衣櫃分髮型、上衣、下身、鞋子、帽子、配件、手持物七部位，點選已收藏道具即可穿戴並自動存檔，每部位只穿一件；「森林日常裝」還原單一部位。小屋、佈置、戰鬥、結算和試穿都共用 `AvatarRenderer`，穿搭不影響戰鬥數值。

商店服裝分頁提供「試穿預覽」，未購買也能預覽角色。試穿只建立畫面副本，不扣款、不改庫存或存檔；結束試穿、切換分類或離開商店即可返回正式外觀。購買後仍由衣櫃選擇是否穿戴。

`outfit-models.json` 定義十款程序式 3D 模型的樣式、顏色與錨點，完整規範見 [docs/OUTFIT-ASSETS.md](docs/OUTFIT-ASSETS.md)。`npm run build` 會先執行資產檢查，CI 也使用相同檢查。舊存檔的合法穿搭可直接沿用；遺失模型、未持有或部位不符的裝扮會還原預設並提示，其他進度保留。

## Phase 5 圖鑑、複習與成就

每單元通關解鎖三篇附圖知識，點閱後保存已讀記錄。道具圖鑑收錄全部家具與服裝，提供真實 3D 彩色預覽／未收藏剪影，以及依內容包產生的商店、關卡或成就取得提示。

從地圖或學習導覽進入「複習小徑」：3D 森林沒有 Boss 或失敗，答對移除錯題並給 2 金幣，答錯保留供重練；複習計入答題統計，不給 XP，已移除的題目不能重複領獎。

五項成就自動檢查並各發獎一次，涵蓋通關、答對 100 題、擺放十件與收藏；新增限定獎盃和佈置旗的 3D 家具。舊進度會補發符合條件的獎勵並立即保存，滿額家具沿用 30 金幣轉換。戰鬥結算金幣與成就獎金分別顯示。

`npm run build` 檢查題池非空、引用、解析及選項位置平衡；目前內建示範包維持五單元、60 題及十五篇圖鑑；展示內容仍須正式教材審核後才能用於教學。

## Phase 6 家長模式與離線

頁面上方進入家長模式，長按 1.2 秒並回答算術題，即可看累計報表、待複習清單，匯出／還原存檔、匯出／加入題庫及切換內容包。離開後重新上鎖。重置須輸入「重新開始」；每份題庫分開保存，最多十份匯入題庫，每檔上限 5 MB。

正式網站顯示「離線遊玩已就緒」後，可斷網重開並完整遊玩；瀏覽器提供安裝／加入主畫面。更新版本需點選「保存並更新版本」，不會在答題中自動刷新。開發模式不註冊 Service Worker，測試離線前先執行 `npm run build`。

閱讀設定提供音效、放大文字與題幹注音。音效預設關閉，使用本機 Web Audio；注音預設開啟，目前五題有示範標注，其餘題目保留原文。資料格式、備份步驟與 PWA 驗證見 [docs/PARENT-AND-OFFLINE.md](docs/PARENT-AND-OFFLINE.md)。

## CF-A／CF-B 本機教材內容工廠

使用 Windows x64、.NET SDK／執行階段 8 與 Node.js 24，先準備再啟動：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Setup-Factory.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start-Factory.ps1
```

開啟 `http://127.0.0.1:5088/`，或從遊戲家長模式進入。教材保存在 `factory-data/`，預設以本機 OCR／規則歸類，不傳送雲端。掃描 PDF 可擷取文字，但所有 OCR 結果都需家長確認；封面／目錄缺字會要求補頁，無課程單元時以固定頁窗暫分並標為待確認。

自製測試教材以 `node scripts/generate-factory-fixtures.mjs` 產生，保存在 `.local/factory-fixtures/`。依使用者要求，測試後不刪除，再次產生也不覆寫同名檔案。十份電子 PDF 與十份掃描 PDF 已驗證，但不能代替真實課本的辨識率驗收。完整流程、API 與設定見 [docs/CONTENT-FACTORY.md](docs/CONTENT-FACTORY.md)。

填空題使用一個 `___` 及 `acceptedAnswers`，戰鬥與錯題複習共用答案判定；同義詞及數學等價寫法由家長明列。產題與審核操作見 [QUESTION-DRAFTS.md](docs/QUESTION-DRAFTS.md)。

產題前可查看候選知識點、複雜度依據及預估題量。新批次以每單元至少二十題為目標，依知識點及複雜度增加，不設上限；來源不足會提示補充內容，未達二十題不會當作完成的單元放行；既有草稿保留原規劃，新批次使用動態題量。

可在「先看試題，再選模型」勾選多個本機模型，用相同知識點各產生兩題，並排看答案、解析及原文。人工比較後點「選用此模型產生題庫」。預覽獨立保存，不會直接混入正式題庫。
